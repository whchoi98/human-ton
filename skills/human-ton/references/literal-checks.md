# 문자열 대조 도구

`scripts/check_literals.py`는 원문과 수정본에 있는 수치·단위, URL, 직접 인용, 코드, 사용자가 지정한 문자열을 비교하는 **보조 도구**다. 의미·인과·격식·자연스러움은 검사하지 않는다.

원문과 결과 파일이 이미 있고 Python 3.9 이상을 실행할 수 있을 때 사용한다. 붙여넣은 짧은 원고를 윤문할 때는 이 도구를 쓰기 위해 별도 파일을 만들 필요가 없다.

```bash
python3 "/설치된/경로/human-ton/scripts/check_literals.py" \
  original.md revised.md \
  --protect "제품 이름" --protect "p95"
```

스크립트 경로는 실제 설치된 스킬 디렉터리에서 찾는다. 현재 작업 폴더에 `scripts/`가 있다고 가정하지 않는다. Codex·Claude·Kiro 전용 환경변수는 필요 없다.

JSON 결과의 종료 코드는 다음과 같다.

| 코드 | 의미 | 후속 작업 |
| --- | --- | --- |
| `0` | 수집한 문자열에 차이를 찾지 못함 | 원문과 의미를 직접 대조한다 |
| `1` | 문자열 추가·누락·변경 후보가 있음 | 해당 구간을 확인한다. 정당한 변경도 후보로 나올 수 있다 |
| `2` | 파일·인자 등 입력 문제 | 입력을 확인하거나 수동 대조로 진행한다 |

`semantic_equivalence: "not_checked"`는 의미 동등성을 검사하지 않았다는 뜻이다. 종료 코드 `0`을 “의미 보존 통과”로 보고하지 않는다.

정규식으로 찾은 문자열과 출현 횟수를 비교하므로 복잡한 Markdown, 모든 언어의 수 표현, 모든 고유명사를 처리하지 못한다. 고유명사나 약어는 `--protect`로 추가할 수 있다. `A는 10%, B는 20%`가 `A는 20%, B는 10%`로 바뀌면 문자열 집합은 같아 통과할 수 있다. “아직 확인되지 않았다”가 “확인됐다”로 바뀐 경우도 별도 의미 검수가 필요하다.

스크립트는 파일을 읽기만 한다. 수정본을 자동 교정하거나 외부 서비스에 보내지 않는다.
