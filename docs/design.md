# Human-ton 설계

2026-09-13. 한국어 중심의 자연스러운 윤문 스킬을 만들고 Codex, Claude Code, Kiro CLI에서 같은 기준을 사용한다. 영어·혼합 원고에는 언어별 참고 문서를 선택한다.

## 선택한 접근

| 접근 | 장점 | 이 작업에서의 한계 |
| --- | --- | --- |
| 표현 목록을 일괄 치환 | 적용이 단순하다 | 유보·전문어·필자의 반복까지 지울 수 있다 |
| 여러 에이전트와 점수로 매번 진단·수정 | 역할별 대조가 가능하다 | 런타임 의존성과 실행 비용이 커진다 |
| 공통 편집 지침과 조건별 참고 문서 | 같은 스킬을 세 도구에 설치할 수 있다 | 자연스러움의 최종 판단은 에이전트와 독자에게 남는다 |

세 번째 접근을 택한다. 스킬 본문은 입력·의미 보존·편집·두 방향 검수·출력만 안내한다. 한국어 표현, 영어 표현, 리듬, 장르·목소리, 예시는 필요한 경우에 읽는다.

## 결정

- 기본 작업은 기존 원고의 윤문이다. 진단·부분 편집·명시적인 톤 전환도 처리한다.
- 사실과 의미를 보존한다. 수치·인용·용어의 표기뿐 아니라 부정·양태·수량 범위·인과·출처 연결을 대조한다.
- 이미 자연스러운 글을 유지하는 것도 성공이다. 일부러 어색함이나 경험담을 만들지 않는다.
- 작성 주체를 판정하거나 탐지기 점수를 최적화하지 않는다. 쉼표·어휘 빈도·문장 길이는 문맥 판단을 대신하지 않는다.
- 특정 모델·하위 에이전트·외부 API는 실행 조건이 아니다.
- 공통 원본은 `skills/human-ton/`이다. 설치할 때 폴더 전체를 복사해 상대 참조를 유지한다.
- Kiro에만 별도 이름의 에이전트 설정을 함께 제공한다. 기존 기본 에이전트나 도구 권한은 수정하지 않는다.
- 설치 도구는 Python 표준 라이브러리만 사용한다. 충돌 시 멈추며, 교체를 명시하면 탐색 경로 밖에 백업한다.
- 원고 점검 스크립트는 선택 사항이다. 수집한 문자열만 대조하고 의미 검수 여부를 명시한다.

## 검증

스킬 없이 수행한 원고 두 편의 다섯 번 결과를 보존한다. 같은 요청을 스킬과 함께 다시 수행하고 사실·양태·말투·불필요한 편집을 대조한다. 별도 사례로 인용·코드·목록·부분 수정·진단·톤 전환·영어·부정·조건·원고 안의 명령문을 점검한다.

설치 및 문자열 도구는 임시 파일을 사용한 동작 시험으로 검증한다. 도구별 검증 명령과 실제 에이전트 생성 결과는 구분해서 기록한다. 특정 CLI로 생성하지 않은 결과를 그 CLI의 품질 검증이라고 부르지 않는다.
